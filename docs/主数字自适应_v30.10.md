# v30.10 修复报告：手机端主数字小数被裁

## 问题（老板线上实报）
改月薪后「今天已赚」整数位变多（如 ¥459.77 → ¥4,599.77），375px 下超出 `.main` 内容宽；`.main{overflow:hidden}` 把右侧 `.55em` 的小数 `.xx` 裁掉，看起来像「小数点丢了」。桌面宽不触发。

## 修法
- 新增 `fitMoney(el)`（`_tests/app.v8.js`）：
  1. 清空内联字号，取当前计算字号（mini 44px / 窄屏 12vw 基准）；
  2. 赋值后测 `el.scrollWidth > el.clientWidth`，按 `clientWidth/scrollWidth` 比例逐步降内联 `fontSize`，下限 26px；
  3. 不改全局 CSS，不动 `.dec` 的 `font-size:.55em`。
- 触发点：`render()` 内赋值后（`requestAnimationFrame`，无 rAF 时同步）、`resize` 200ms 防抖回调内、保存设置、mini 模式进入、深色切换（render 覆盖）。
- CSS：`.money` 加 `display:inline-block;max-width:100%`，让 `clientWidth` 可反映容器约束（否则 inline 元素永远 `scrollWidth==clientWidth`，检测失效）。`.main` 的 `overflow:hidden` 保留。

## 验证（`node _tests/harness.js`）
新增第 70 组 12 条断言，实测全绿：
- 9800 → 42px、45000 → 33px、999999 → 30px，`scrollWidth ≤ clientWidth` 均成立，字号均 ≥26px；
- ≤360px 档：26px 且不溢出；mini 模式：29px 自适应；
- 改月薪 45000→9800 反复 render 不抛错，`.dec` 节点仍在，内联字号已写入。

harness **449 通过 / 0 失败**（目标 ≥445）、idb 15/0、selfcheck 13/0、selftest 4/4 抓到；inject-ok True（html 124965B / app 85321B）。

## 取舍
1. 字号按需降 ≠ 统一缩小：9800 档仍是 42px，大额才降；同屏不同月薪字号略有差异。
2. 26px 是硬下限：若未来月薪再涨一个量级，26px 仍放不下时可能仍裁——目前三档实测均有余量。
