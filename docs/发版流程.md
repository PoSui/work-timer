# 发版流程（牛马计时器）

> 2026-11-04 用户定下的硬规矩：**每一版更新后，都要交给产品经理 agent 测试**，产品过了才算交付。

## 一、版本推进顺序（不可跳步）

```
改代码 → 本地测试台全绿 → 提交（本地） → 派 pm 验收 → pm 出报告
   → 有问题：修 → 重新走一遍
   → 没问题：推 GitHub（API 推送，沙箱不能 git push）→ Cloudflare 自动部署 → 用户刷新验证
```

**禁止**：没跑测试就提交、没让 pm 验收就推线上。

## 二、每一步的判定标准

| 阶段 | 谁做 | 通过标准 |
|---|---|---|
| 1. 改代码 | 开发（java-dev / lead） | 只改 `_tests/app.v8.js`，再 `python _tests/inject.py` 重新注入 `index.html` |
| 2. 本地测试 | 开发 | `node _tests/harness.js` 全绿 + `node _tests/idb.test.js` 全绿 |
| 3. 提交 | 开发 | `git -c user.name=PoSui -c user.email=posui@users.noreply.github.com commit`（本机没配全局身份） |
| 4. 产品验收 | **pm** | 按第三节清单逐项过，输出 `docs/验收报告_<版本>.md`，结论只有「通过 / 不通过（列问题）」 |
| 5. 推送 | lead | 产品通过后才推；推完记 commit 号 |
| 6. 线上验证 | 用户 | 刷新 `https://work-timer-7av.pages.dev/` |

## 三、产品验收清单（每一版都过一遍）

**A. 首次打开**
1. 直接打开页面：不弹空向导，主数字显示 ¥0.00，状态「未开始」
2. 时薪/日薪已按默认值显示（月薪 9800 → 时薪 64.37、日薪 450.57）
3. 设置区 8 个字段全部有值，没有 `--:--`、不空白

**B. 计时**
4. 点「开始上班」→ 状态变「工作中」，数字从「上班时间到现在」的金额开始跳
5. 数字每秒在动（不是静止）
6. 倒计时显示到下班还有多久
7. 午休时段不涨钱
8. 点「下班存档」→ 状态「今天已下班」，金额冻结

**C. 钱的口径**
9. 「今天已赚」= 今天有效工时 × 时薪
10. 「本期已赚」= 发薪周期内每天累加（默认 15 号发薪 → 账期 10-16~11-15）
11. 日历：过去工作日自动变绿并显示 ¥450.57；周末/法定假灰；今天绿框
12. 点过去的工作日 → 出现菜单（正常上班 / 休息 / 带薪假 / 病假 60% / 上班 80% / 加班 1.5·2·3 倍），选完日历与「本期已赚」同步变

**D. 攒钱目标**
13. 点「+ 添加」能弹输入框加目标；目标进度条有颜色填充；点金额能改目标值
14. 达到目标显示 ✅ 并排到后面

**E. 其他**
15. 「本期构成」按月统计各类型天数与金额，合计对得上
16. 导出 CSV 能下载且列齐全；导出备份 JSON 能下载；导入备份能恢复记录与目标
17. 小窗按钮 `?mini=1` 打开紧凑版；主题切换按钮可用
18. 文案不绕：「点开始上班 = 从上班时间算到现在，再继续跳」这类说明读得懂

## 五、已知的环境限制（pm 也要知道）

- 沙箱里**起不了浏览器**（子进程被禁），所以 pm 的验收靠：读 `index.html` 源码 + 跑 node 测试台 + 对照本清单逐条核对逻辑，**不能真的点页面**；真正点击由用户完成。
- 沙箱里 **`git push` 不可用**（`cannot create standard input pipe`），推送由 lead 用 GitHub API 脚本做。
- 无浏览器截图能力（Edge 无头 `exit 3`），UI 视觉问题只能靠用户截图反馈。

## 六、版本号规则（2026-11-04 用户定，防止版本号膨胀）

| 改动性质 | 版本号 | 例子 |
|---|---|---|
| **新增功能 / 大改** | 整数进位：v25 → v26 → v27 | 加「攒钱目标」= v25 |
| **只修 bug** | 两位小数：v26.01、v26.02（同一大版本下累加） | 修「设置区空白」= v26.01 |
| 小版本攒够 / 又有新功能 | 进位成大版本，小数清零 | v26.03 之后上功能 → v27 |

规则细则：
1. 版本号唯一来源：`index.html` 里的 `<div class="brand">牛马计时器 · vNN[.0X]</div>`，同时同步 README「版本历史」。
2. **一个 bug 一个提交**，提交信息以版本号开头，例如 `fix(v26.01): 补回计薪方式下拉…`。
3. git tag 与版本号同名：`v26`、`v26.01`。
4. **小版本号最多到 .99**，再修就进位大版本，避免出现 v26.37 这种长尾。
5. 每个版本（无论大小）都必须：本地测试全绿 → pm 验收 → 才 push。
