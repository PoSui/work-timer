# 手机端逐屏 UX 审查 v1

> 依据：tag v30.05 源码 + 用户三张手机截图描述；按 320 / 375px 推演。标 **（v30.06 已派）** 的是开发已接的 8 条，其余是本次新发现。
> 流程补丁：从 v30.06 起，每版验收必须加一条 375px 检查（无横向溢出 + 首屏 CTA 可见 + 触控热区），结论写进验收报告，不再让用户代做 QA。

## 1. 首屏（主卡）

| 现象 | 用户为什么觉得错 | 建议改法 |
|---|---|---|
| 375×812 下要滚动才看到「开始上班」：3 个进度条 + 3 小卡 + 说明 + 小结把 CTA 推到 ~700px 以下 | 打开工具的第一动作（开始计时）不在视野里，像"页面没加载完" | 手机档把「本期进度」「今天有效工时」收进「更多数据」折叠，主卡只留「今天进度」；或给 CTA 做底部吸底 |
| 「本期已赚」小卡和下面「本期进度」条重复表达同一件事 | 首屏信息密度高但重复，用户扫一眼不知道先看哪个 | 手机只保留小卡，进度条在桌面显示；或在手机把两张合并成一张 |
| 顶栏品牌写「牛马计时器 · v30.05」，320px 下挤压状态徽章/主题按钮 | 品牌+版本抢了操作区宽度，状态容易被挤成两行（v30.05 暂无溢出断言） | 品牌只显示「牛马计时器」，版本号放 `<title>`；`.state` 与主题各保留 44px 热区 |
| 说明行「点开始上班 = 今天从上班时间起补算，之后每秒自动加钱」占 2–3 行 | 首屏最贵的空间用来解释一个按钮，且"补算"仍绕 | 缩成「点开始，按秒算钱」；口径说明放进「?」抽屉 |

## 2. 日历

| 现象 | 用户为什么觉得错 | 建议改法 |
|---|---|---|
| 标题 right 的 tag 太长（「10-16 → 11-15（11-15 发薪）· 已过 14/31 天 · 工作日 13 天」），把 h2 挤成竖排 **（v30.06 已派）** | 标题逐字竖排像排版坏了 | 手机档 h2 只留「发薪周期日历」，tag 移到下一行小字或只留「10/16–11/15」 |
| 7 列格子在 375px 下每格约 41px，格内「¥450.57」10.5px 需 ~45px+，撑破/横向溢出 **（v30.06 已派）** | 数字出格、格子参差，看起来像页面坏了 | `.cal` 改 `repeat(7,minmax(0,1fr))`；手机金额只显示「450」或缩到 9px + `nowrap/ellipsis` |
| 标题同时出现「已过 14/31 天」和「工作日 13 天」，用户读成 14≠13 的矛盾 **（v30.06 已派）** | 两个「天」混在一句，口径没分开 | 拆两句并统一口径：「本期 13 个工作日 · 已过上班日 10 天」；日历上不再报"已过 X 天" |
| 日历卡高约 400px+ 且紧跟主卡，攒钱目标/对账被推到第 3–4 屏 | 用户每天要看的「攒了多少」被日历压在后面 | 手机档整卡折叠（标题行显示账期），默认收起，点开再渲染 |
| 底部说明「点本期内过去的工作日，可选…」占 3 行灰色小字 | 手机首屏变长，且这段是低频操作说明 | 收进标题旁的「?」或首次使用时一次性提示 |

## 3. 攒钱目标

| 现象 | 用户为什么觉得错 | 建议改法 |
|---|---|---|
| 多个目标全部展开，每个都带进度条 + 「还差 ¥X · 约 N 个工作日（日期 左右）」 | 3 个目标就占一屏，越长越像报表 | 手机默认只展开「最接近达成」1 个，其余折叠为「全部 N 个目标」列表，行内只留名称+进度 |
| 「+ 添加」小按钮在标题右侧，点开后 4 个输入纵向铺开、保存/取消在最底部 | 手机上要滚到表单底部才能保存，像网页版缩小 | 表单改底部抽屉，字段紧凑排列，保存按钮固定可见 |
| 达成显示「已达成 🎉」 | 产品基调是"不庆祝不催"（对账已刻意去庆祝），这里破例 | 改成「已达成」；如要保留情绪价值，最多加一个 ✅ |
| 目标行只有「金额可点改」和「× 删除」，没有改名称入口；× 热区小 | 建错名字只能删了重建；手机上容易误删 | 点目标名进编辑（名称/金额一起改）；× 热区 ≥44px + 确认 |

## 4. 本期构成

| 现象 | 用户为什么觉得错 | 建议改法 |
|---|---|---|
| `.srow` 固定四列 `74px 46px 1fr 78px`，320px 下中间列只剩 ~50px，日期/说明挤到换行 | 表格像被压扁，读不成行 | 手机改两行式：第一行「10/16 周一」+ 金额右对齐，第二行小字「正常 · 8h」 |
| 金额列没有 nowrap，长金额（¥10,000.00）会撑破列宽 | 数字串行、行高跳动 | 金额 `white-space:nowrap; text-align:right`，必要时缩到 12px |
| 合计行和明细同字号、无分隔 | 看不出"总计"在哪，扫读失败 | 合计加粗 + 浅底色分隔，与明细拉开层级 |

## 5. 月末对账

| 现象 | 用户为什么觉得错 | 建议改法 |
|---|---|---|
| `.act3` 三格并排，19px 的「¥5,406.90」在 327px 内容宽下每格约 100px，金额撑破/换行 | 三个核心数字被挤成两行，最该看清的地方最乱 | 手机改纵向 3 行（或 2×2），金额 16–17px + nowrap |
| 标题右侧 tag「满勤应得 vs 到手」比 h2 还长 | 标题被压缩，卡片头显得拥挤 | 手机档隐藏该 tag，把口径放进卡片说明 |
| 结果视图先给三个大数字和长解释，结论「差额主要来自…」在下面 | 用户滚半天才看到"到底差在哪"，核心信息迟到 | 结论句置顶（紧跟三数字），归因明细放后面 |
| 表单里代扣折叠在底部，键盘弹起后「保存」可能被遮 | 手机上填完不知道点哪 | 表单改底部抽屉，按钮 sticky 在键盘上方 |

## 6. 时薪轨迹

| 现象 | 用户为什么觉得错 | 建议改法 |
|---|---|---|
| summary 左侧有 ▸ 箭头、右侧又有「折叠」tag，形成两个折叠信号 **（v30.06 已派）** | 用户以为有两个入口，或不知道 tag 能不能点 | 删掉 tag，只留箭头；文案改「时薪轨迹」 |
| 只有 summary 一行可点，卡片标题区/空白处点击无反应 | 手机上点卡片没反应，像坏了 | 整个卡片头可点，或 summary 热区撑满整行 ≥44px |
| 折线 X 轴按序号排、不标真实月份；327px 下首末标签贴边 | 用户读不出"这是哪几个月"，时间感丢失 | 手机只标首/末两个真实年月（如 2025-06 / 2026-11），中间点不标字 |
| 「同样 8 小时 ¥462.40 → ¥788.18」没解释 8 小时是标尺 | 用户可能以为是自己的实际工时 | 加一行小字「按每天 8 小时折算，仅作对比」 |

## 7. 近 6 个月

| 现象 | 用户为什么觉得错 | 建议改法 |
|---|---|---|
| 0 元月份柱高 2px，柱顶金额标签 `top:-17px` 全部贴底重叠；X 轴月份错乱 **（v30.06 已派）** | 一排「¥0.00」叠在一起，像图表渲染失败 | 手机只画最近 3 个月（优先有数据月）；0 元月只留月份不画柱，标签只在 >0 时显示 |
| 6 根柱挤在 327px，每根约 45px，柱顶标签几乎相接 | 图表读不出趋势，只剩装饰 | 手机 ≤3 柱；柱宽自适应，金额标签放柱内或柱下 |
| 6 个月都没数据时仍画 6 条 2px 柱 + 0 元标签 | 空状态像坏图 | 给空状态文案「还没有足够数据，上几天班再来看看」 |
| 图表没有预留顶部空间，柱子最高时标签可能压到卡片标题 | 视觉上层级混乱 | 图区加 `padding-top:20px`，标签定位在柱顶但不出图区 |

## 8. 设置

| 现象 | 用户为什么觉得错 | 建议改法 |
|---|---|---|
| summary「设置 · 工资 / 上下班 / 午休 / 发薪日 / 休息制度 / 加班倍率」在 327px 换 2–3 行、中文断词难看 **（v30.06 已派）** | 折叠标题像一段正文，用户找不到"设置"入口 | summary 只留「设置」+ 右侧「展开」；副标题放展开后的第一行 |
| 长 label「月薪（到手或应发，元）」占两行，输入框被推低 | 表单像 squeezing，一屏填不完 | label 精简为「月薪」，括号说明改 placeholder |
| 导出 CSV / 备份 / 恢复默认 / 清空全部数据混在设置底部 | 「设置」和「数据操作」语义不同，手机上滚到底容易误触清空 | 拆独立「数据与备份」折叠；清空放最底、红色按钮 + 现有三连确认 |
| 计薪方式切到「按日薪 / 按时薪」后，年薪月数等字段仍显示 | 用户不知道哪些字段还有效 | 随选择隐藏无关字段，并在切换时给一句「日薪 = 月薪 ÷ 每月工作日」 |

## 9. 跨屏与流程

- 8 张卡纵向约 4–5 屏，没有吸顶摘要/锚点：建议顶栏 sticky 显示「今天 ¥X · 本期 ¥Y」，滚动时始终可见（也缓解首屏 CTA 问题）。
- 卡片顺序建议（手机）：主卡 → 攒钱目标 → 本期构成 → 月末对账 → 时薪轨迹 → 近 6 个月 → 日历（折叠）→ 设置；日历是低频查看，不该排第二。
- 触控热区统一 ≥44px：目标「×」、日历格、`.chip`、折叠 summary 都要过一遍；相邻按钮 gap ≥8px。
- 每版验收固定加「375px 三项」：① `scrollWidth<=innerWidth`；② 首屏 CTA 在 812px 高度内可见；③ 主数字/金额不被裁。写进 `docs/移动端规格.md` 与验收报告。
