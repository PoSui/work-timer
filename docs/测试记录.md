## 已知取舍（按版本）

### v26.03（1 条）

1. **默认值不预填 9800**：避免把某一个人的工资当成产品默认；代价是首次打开必须经过向导（点「先随便看看」也会被拦下提示）。

### v27（3 条）

1. 归因最多显示 3 条（按影响金额降序），四种异常同时出现时影响最小的一类（通常是带薪假 ¥0）可能被挤出列表。
2. 结论句只用「有实际影响」的条目（|影响| ≥ 0.005 元）；带薪假可能在列表里显示但不会写进结论。
3. 归因基数用**当前**日薪；对账后改月薪，旧账 estimate 不变，但重新打开结果视图时归因金额会按新口径重算（v28.01 后仍存在的已知项，见其第 2 条）。

### v28（4 条）

1. 抽屉数字复用主界面函数，没有另写算式；但「有效工时」拆解与 `workMsOf` 共用 `workSplit`，仍是同一套实现。
2. 时薪抽屉里的 21.75 是**月均**计薪天数，当月实际工作日不同会有几十元偏差，文案已说明可在月末对账校准。
3. 抽屉为纯前端展示层，数据来自当前页面状态；改设置后重新打开抽屉会按新口径显示（与主界面一致）。
4. 本期抽屉的分类型金额来自 `periodGroups`，与统计卡「本期构成」同源；「加班 ×倍率」列出本期出现过的倍率。

### v28.01（7 条）

1. **满勤基准不含今天**：只累加「已经过完的工作日」，今天的钱还在实时变，纳入会让对账数字一天之内反复跳。
2. **满勤按当前日薪算**：归因基数用当前设置的日薪；对账时即把归因结果与基准快照化（见 v28.02），此后面改月薪、改作息，旧账的归因金额与结论都不会变。
3. **归因最多显示 3 条**：四种以上标记同时出现时，影响最小的一类（通常是带薪假 ¥0）可能不显示在列表里，但仍参与抵消与残差计算。
4. **「基本抵消」是经验阈值**：正负影响净额 < max(50 元, 较大一侧的 20%) 视为基本抵消；阈值是经验值，不是精确规则。
5. **残差提示阈值 100 元**：|残差| > 100 元才提示「暂未归类」；小于 100 元只写「零头差异」，避免把几块钱的折算误差说成社保/个税。
6. **代扣只做加总**：社保/公积金/个税三项加总后从满勤应得里扣，参与结论与残差；不区分每一项各自造成多少差额。
7. **大额提醒是经验阈值**：实发 > 满勤应得 3 倍或 < 0.3 倍时提醒「可能多打一位 / 只发了一部分」，仅提示，不阻止保存。

### v28.02（4 条）

1. **快照 = 保存那一刻的口径**：`basis/dailyPaySnapshot/paidDaysSnapshot/impactSnapshot` 都固化在记录里；之后改月薪/作息不影响旧账，也不会自动重算——想按新口径看，得重新保存一次。
2. **老记录不自动补快照**：v28.01 及更早存的对账没有这些字段，打开时降级为按当前口径重算并明确标注；只有用户再点「保存」才会补写快照并固定说法。
3. **快照只存聚合结果**：`impactSnapshot` 是「类型 / 天数 / 金额」，不含逐日明细，所以结果视图无法回溯「具体哪一天」；逐日数据仍在日历与记录里。
4. **多存字段向后兼容**：localStorage 与 IDB 快照都会多带这几个字段，旧版本代码读取时忽略未知字段，不影响原有读取。
