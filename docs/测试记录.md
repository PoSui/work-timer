## 已知取舍（按版本）

### v26.03（1 条）

1. **默认值不预填 9800**：避免把某一个人的工资当成产品默认；代价是首次打开必须经过向导（点「先随便看看」也会被拦下提示）。

### v27（3 条）

1. 归因最多显示 3 条（按影响金额降序），四种异常同时出现时影响最小的一类（通常是带薪假 ¥0）可能被挤出列表。
2. 结论句只用「有实际影响」的条目（|影响| ≥ 0.005 元）；带薪假可能在列表里显示但不会写进结论。
3. 归因基数用**当前**日薪；对账后改月薪，旧账 estimate 不变，但重新打开结果视图时归因金额会按新口径重算（v28.01 后仍存在的已知项，见其第 2 条）。

### v28（4 条）

1. 抽屉数字复用主界面函数，没有另写算式；但「有效工时」拆解与 `workMsOf` 共用 `workSplit`，仍是同一套实现。
2. 时薪抽屉里的 21.75 是**月均**计薪天数，当月实际工作日不同会有几十元偏差，文案已说明可在月末对账校准。
3. 抽屉为纯前端展示层，数据来自当前页面状态；改设置后重新打开抽屉会按新口径显示（与主界面一致）。
4. 本期抽屉的分类型金额来自 `periodGroups`，与统计卡「本期构成」同源；「加班 ×倍率」列出本期出现过的倍率。

### v28.01（7 条）

1. **满勤基准不含今天**：只累加「已经过完的工作日」，今天的钱还在实时变，纳入会让对账数字一天之内反复跳。
2. **满勤按当前日薪算**：归因基数用当前设置的日薪；对账时即把归因结果与基准快照化（见 v28.02），此后面改月薪、改作息，旧账的归因金额与结论都不会变。
3. **归因最多显示 3 条**：四种以上标记同时出现时，影响最小的一类（通常是带薪假 ¥0）可能不显示在列表里，但仍参与抵消与残差计算。
4. **「基本抵消」是经验阈值**：正负影响净额 < max(50 元, 较大一侧的 20%) 视为基本抵消；阈值是经验值，不是精确规则。
5. **残差提示阈值 100 元**：|残差| > 100 元才提示「暂未归类」；小于 100 元只写「零头差异」，避免把几块钱的折算误差说成社保/个税。
6. **代扣只做加总**：社保/公积金/个税三项加总后从满勤应得里扣，参与结论与残差；不区分每一项各自造成多少差额。
7. **大额提醒是经验阈值**：实发 > 满勤应得 3 倍或 < 0.3 倍时提醒「可能多打一位 / 只发了一部分」，仅提示，不阻止保存。

### v28.02（4 条）

1. **快照 = 保存那一刻的口径**：`basis/dailyPaySnapshot/paidDaysSnapshot/impactSnapshot` 都固化在记录里；之后改月薪/作息不影响旧账，也不会自动重算——想按新口径看，得重新保存一次。
2. **老记录不自动补快照**：v28.01 及更早存的对账没有这些字段，打开时降级为按当前口径重算并明确标注；只有用户再点「保存」才会补写快照并固定说法。
3. **快照只存聚合结果**：`impactSnapshot` 是「类型 / 天数 / 金额」，不含逐日明细，所以结果视图无法回溯「具体哪一天」；逐日数据仍在日历与记录里。
4. **多存字段向后兼容**：localStorage 与 IDB 快照都会多带这几个字段，旧版本代码读取时忽略未知字段，不影响原有读取。

### v29（7 条）

1. **折线用原生 SVG**（不是纯 CSS 拼线段）：比 CSS 旋转拼线段稳、可打点标字，仍不引任何图表库；代价是极老浏览器（IE）不支持 SVG。
2. **阶段只记薪资变化，不记同月内每次微调**：同月以最后一次保存为准，避免一个人一个月改三次就多三段。
3. **改天数/工时也会追加阶段**：口径变了就是新阶段（时薪 = 月薪 ÷ 天数 ÷ 小时，任一变化都影响时薪）。
4. **「同样 8 小时」固定用 8 做标尺**，不跟随当前设置里的工时，为的是跨阶段可比。
5. **工资为 0 时不生成阶段**：避免出现「¥0 阶段」把曲线拉歪；设置里填了月薪后（保存时）才生成第一段。
6. **涨跌幅按「首段 vs 末段」**：中间阶段只参与画线，不进结论句；阶段很多时结论仍是一句话。
7. **阶段起始月允许任意编辑、不强制排序**：图表按数组顺序画；用户把月份改乱时曲线顺序会跟着乱（尚未加排序校验）。

### v30（7 条）

1. **存档不再二次确认**：误点会直接存档，靠「继续计时（回滚存档）」恢复；这是「安静」的代价，换来不打断的下班瞬间。
2. **「这个月第 N 天」按自然月计**，不是发薪周期；发薪日不是 1 号时，这个数字与本期的「工作日数」不是一回事。
3. **「累计」只统计已存档的日子**（记录里的 earned），没记录的日子不计入，也不按当前日薪补算，避免改月薪后历史累计跳动。
4. **展开状态不记忆**：刷新、重新计时后一律回到收起；不写入 localStorage。
5. **抵消合并有阈值**（与结论同一套）：正负项抵消 ≥90% 才合并成一行「（净 ¥0.00，基本抵消）」，部分抵消仍分行并标「基本抵消」。
6. **「多打一位」提醒不扣代扣**：实发 > 满勤应得 3 倍仍无条件提醒（宁可信其有）；「只发一部分」的判断改为先扣已填代扣。
7. **无动效/音效/徽章**：这是 v27 爽感被否后的产品基线；小结只有一行字，展开是纯文本三行。

### v30.01（4 条）

1. **同月「+ 添加一段」= 覆盖末段**：同一个月留不下两次不同薪资，月内以最后一次为准（避免曲线在一列里堆点）。
2. **非法月份静默拒绝**：只把输入回弹成原值，不弹错误条（保持安静），用户可能一时不知道为什么没改上。
3. **编辑月份后自动按时间排序**：改完那一行可能跳到别的位置；排序是稳定排序（同月按薪资），但不做动画提示。
4. **月薪为 0 时轨迹只给提示**：显示「现在还没填月薪」，不再用最后一段历史时薪冒充「现在值」；历史阶段仍照常画。

### v30.02（2 条）

1. **「上班日」只数真上了的**：`earned>0` 才计数；标了休息/带薪假但当天其实来了的人，天数不会计入（金额仍按记录口径，只影响文案）。
2. **0 元记录不算一天**：例如加班但金额为 0、或手动清空金额的存档，不进「第 N 个上班日」；累计金额也不加 0。

### v30.03（3 条）

1. **主数字仍是渐变 clip**：深色下换成亮 token（`#4FD1C5 → #7BE495`）保证对比 ≥8，但严格说仍是「背景剪裁」而非实色填充；CSS 不支持 `background-clip` 的旧内核会退化成透明字（当前目标浏览器都支持）。
2. **深色层级靠明度差 + 1px 描边 + 阴影**：常规描边 `--line=#354C60` 对卡片只有 1.19 对比，低于 spec 的强描边 4.06；极暗屏/低亮度下卡片边界会偏软，靠阴影补。
3. **深色覆盖率靠 token + 逐组件手写**：64 组只校验了主要面与文字/进度条/三态，未做全组件快照对比；JS 里仍有少量内联 alpha（阴影 `rgba(0,0,0,.42)`），深色下是固定值，不随主题变。

### v30.04（3 条）

1. **手机只隐藏入口，不砍能力**：`?mini=1` 链接在手机上仍可用（有人从书签打开时也不至于白屏），只是不再暴露「小窗」按钮。
2. **只有一个 ≤720px 断点**：721–900px 的平板中间态仍是三栏，靠 `minmax(0,1fr)` 收缩不至于溢出，但会偏挤；等有真机再补断点。
3. **窄屏按钮改成整行/等分**：开始上班整行、存档/继续计时均分，牺牲桌面那种紧凑排布换拇指可点面积。

### v31（2 条）

1. **只有主数字 3 位**：抽屉里的「今天已赚」仍是 2 位（`moneyHTML` 默认值），同一数字两处精度不同，是有意收敛影响面。
2. **降级不可逆感**：窄屏降到 2 位后回宽屏会在下一次 render/重算时恢复 3 位，但当前窗口不变时会保持 2 位（避免来回抖动）。

### v30.10（2 条）

1. **字号按需降，不做统一缩小**：9800 档手机上仍是 42px（略小于设计 45px 上限），只有大额才降到 30px 左右；视觉上同屏不同月薪字号会不同。
2. **极端情况仍可能触底 26px**：若月薪再涨一个数量级（10 万+），26px 也放不下时会保留最后一级字号并可能仍裁切——目前三档实测都在 26px 以上且不裁，但这不是无限保证。

### v30.09（2 条）

1. **版本自检要求台账先更新**：发版顺序必须是「升版本 → 写台账行（commit 先占位）→ 跑自检 → 提交」，否则严格相等会 red；这是有意的门禁。
2. **`--selftest` 只证明「检查逻辑能抓到故障」**：4 类故障固定（id/版本历史/innerHTML），不覆盖 CSS 括号与对比度；这两项靠正常模式本身。

### v30.08（3 条）

1. **320px 金额取整**：≤360px 只显示「¥460」，月度明细要看两位小数得点开对账/导出；换取不截断。
2. **日历折叠只在跨断点瞬间生效**：从桌面直接打开窄屏仍是折叠；桌面窗口慢慢拖窄不会展开也不会抖动，但用户拖动过程中不会实时收（200ms 防抖后只动作一次）。
3. **自检脚本是静态/估算，不是真机渲染**：id、括号、版本、对比度可自动；「标题是否竖排、金额是否真放得下、首屏是否真的不用滚」仍要靠人眼/真机。

### v30.07（2 条）

1. **手机标题按「有数据的月份数」写**：数据稀疏时标题会变成「近 1 个月」，而查询窗口其实是 3 个月；选择「数字不撒谎」优先于「窗口描述准确」。
2. **全 0 空态下标题仍是窗口月数（近 3 / 近 6 个月）但柱数为 0**：「标题月数 === 柱数」这条不适用于空态（此时没有柱，显示的是「还没有足够数据」）。

### v30.06（4 条）

1. **手机端只用 CSS `order` 重排，DOM 顺序没动**：视觉上按钮提前、日历后置，但读屏/自定义样式的顺序仍是旧的；彻底可访问应移动 DOM，这版优先低风险。
2. **日历默认折叠靠 boot 时 JS 置 `open=false`**：只在窄屏初次加载生效，从桌面缩到手机不会自动折；桌面仍默认展开。
3. **手机图表只画最近 3 个月、0 值月隐藏**：卡片标题仍写「近 6 个月」，手机上实际是 3 个月；数据稀疏时可能只剩 1–2 根柱。
4. **「今天进行中」只解释 1 天差**：构成天数与满勤工作日正常差 1；若今天没上班但今天仍计入构成（有记录/工作日标准日薪），或账期里存在特殊标记，差异可能不是 1，届时需要看构成明细而不是只看总数。

### v30.05（2 条）

1. **快捷键变成「隐含能力」**：界面上不再有任何「按空格可以开始」的说明，新用户不会自己发现；这是用户明确要求（「这有什么值得留下的吗」），不是遗漏。
2. **移动端规格与实现的 clamp 已对齐为 40–72**：桌面主数字上限也从 84 降到 72（v30.04 起全档统一），极宽屏上数字比旧版小一号；换来各档字号一致、少一套断点。
