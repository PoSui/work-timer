# 深色模式配色规格 v1

> 目标：把深色模式从「深底上贴白卡片」改成**一套有层级的深色界面**——背景最深、卡片次之、控件再抬一层，全靠明度差 + 1px 描边分层，不靠纯白提亮；所有文字/状态在暗底上满足 WCAG AA。
>
> 依据：`index.html` 现有 CSS（`:root` 变量 `:8-10`、`body.dark` 规则 `:186-195`、各组件硬编码色值）。本文只给规格，不改代码。

## 0. 现状诊断（为什么截图显得潦草）

`body.dark` 目前只覆盖了 `.card / h2 / sub / input / .cal .d / .bar / .stat .k / #sheet / .day-sum` 等少数选择器，大量组件仍落在浅色画布上：

| 位置 | 现状 | 后果 |
|---|---|---|
| `index.html:39` `.chip` | 用 `var(--card2)`，而深色模式没有覆盖 `--card2`（仍是 `#f7fbfe`） | 三栏小卡纯白，最刺眼 |
| `:21` `.state` | `background:#fff` | 顶部「工作中/未开始」白底 |
| `:59-61` `.b-stop / .b-ghost`、`:154` `.mini-btn` | `background:#fff` | 顶部「小窗 / 🌙 浅色」按钮比内容还亮 |
| `:111` `.cal .d` | `background:#fff`，且 `:112/118/120/124/125/128` 的 `.out/.holiday/.makeup/.done/.offday/.future` 仍是浅色底；它们的选择器权重高于 `body.dark .cal .d` | 日历里一块块白/浅红/浅灰格子 |
| `:94` `.mbox`、`:135` `.menu`、`:204` `#sheet`（已单独覆盖）、`:231` `.ph-in` | 白底弹窗/菜单/输入框 | 打开弹层瞬间闪白 |
| `:79` `.tag`、`:105` `.act3` | `#f8fbfe / #f7fafc` 浅底 | 标签、对账三格仍是白片 |
| `:245` `#errBar`、`:436` `#actWarn` | 写在元素 **inline style** 里的浅色 | 样式表无法覆盖，报错/提醒仍是浅色条 |
| `:194` `.bar` | 只改了轨道（`#1d2d3a`），描边仍 `#e3edf6`；`.bar-top` 的 `var(--dim)` 未覆盖 | 轨道近乎看不见，右侧「32.9% · 还差 ¥302.29」发灰 |
| JS 内联色（`#c0392b/#22a06b/#e08a12/#4aa8f0` 等） | 为浅底设计 | 暗底上偏暗、发飘 |

结论：不是调几个色就完事，需要**先补一套深色 token，再按组件覆盖硬编码白底**。下面规格按这个顺序给。

## 1. 色板 token 表

设计取向：深蓝黑打底（不是纯黑，避免 OLED 上死黑断层），卡片用「比页面亮一档」的深灰蓝，控件再亮一档。对比度为实算值（WCAG 2.1 相对亮度公式）。

|---|---|---|---|---|---|
| `--bg` | `#070D13` | 页面最底层 / 小窗模式背景 | 对卡片 `#182633` | 1.27:1 | 非文本，见原则 |
| `--bg2` | `#0D1922` | 页面径向/线性渐变终点 | 对卡片 | 1.22:1 | 非文本 |
| `--surface-1` | `#182633` | 卡片、日历格、弹窗底 | 对 `--bg` | 1.27:1 | 明度差 ≥1.2 |
| `--surface-2` | `#20323F` | 三栏小卡、控件面、菜单、标签、对账三格 | 对卡片 | 1.17:1 | 明度差 ≥1.1 |
| `--surface-3` | `#293F50` | 输入框、hover、按下、提升面 | 对卡片 | 1.41:1 | 明度差 ≥1.3 |

## 2. 明暗对照原则（硬规则）

1. **深色下不允许纯白面**：任何 `background` 不得是 `#fff` / `#ffffff` / `rgb(255,255,255)`。白色只允许出现在**主按钮上的文字**（对比度 4.98:1 达标）和图标描边。
2. **卡片不用白，用比背景亮两级的深灰蓝**：`--surface-1 #182633`；卡片内再抬一层用 `--surface-2 #20323F`；输入/悬停用 `--surface-3 #293F50`。
3. **层级靠三件事**：① 明度差（≥1.17:1）；② 1px 描边（`--border #354C60`；需要识别交互边界时 `--border-strong #6A8799`）；③ 阴影（卡片 `0 6px 22px rgba(0,0,0,.42)`，弹窗 `0 24px 60px rgba(0,0,0,.5)`）。
4. **不用纯黑底**（`#000`）：页面用 `#070D13` 起步、渐变到 `#0D1922`，避免 OLED 上边缘断层与死黑压迫感。
5. **暖色只用在小面积语义**（金色/警示/错误条），大面积仍是冷灰蓝；否则暗色会「花」。
6. **明暗两套 token 同构**：浅色保留现有值；深色只覆盖变量 + 必要的组件规则，不改布局、不改字号、不加动效。

## 3. 对比度硬指标（WCAG 2.1 AA）

| 内容类型 | 最低要求 | 本规格实际 |
|---|---|---|
| 正文 / 小字（<18.66px bold 或 <24px） | 4.5:1 | 主 13.37、次 8.96、弱 6.61（弱字在控件面 5.67、抬起面 4.69） |
| 大字（≥24px 或 ≥18.66px bold） | 3:1 | 主数字渐变 8.25 / 9.81 |
| 次要信息 / 标签（仍建议按小字） | 3:1（本规格统一按 4.5） | 表头 6.61、抽屉注释 8.33 |
| UI 组件边界 / 状态指示 / 图形 | 3:1 | 按钮描边 3.48、进度填充对轨道 3.19、状态描边 3.39 / 3.10 / 3.48、今日环 10.41 |
| 装饰性分隔线 | 无要求 | 表格线 1.28、卡片描边 1.73（靠阴影辅助） |

计算方式：相对亮度 `L = 0.2126R + 0.7152G + 0.0722B`（sRGB 线性化后），对比度 `(L1+0.05)/(L2+0.05)`。上表所有比值均由脚本按最终 hex 实算，可直接写进验收。

## 4. 状态色（工作中 / 已下班 / 未开始）

暗色下不能只用「绿→灰」两档，否则已下班和未开始难分。三态用**色相 + 文字 + 圆点**三重区分：

| 状态 | 文字 | 底 | 描边 | 圆点 | 文字对比 |
|---|---|---|---|---|---|
| 工作中 | `#D1FAE5` | `#12352B` | `#3A8F6C` | `#34D399` | 11.80:1（边/底 3.39:1） |
| 已下班 | `#DBEAFE` | `#12304A` | `#3E7FA6` | `#7DD3FC` | 11.12:1（边/底 3.10:1） |
| 未开始 | `#CBD5E1` | `#20323F` | `#6A8799` | `#94A3B8` | 8.90:1（边/底 3.48:1） |

`暂停`（午休）沿用暖色：底 `#3A2A12`、边 `#6B5220`、字 `#F8D48A`（9.72:1），与三态区分。

实现建议：`.state` 前加 6px 圆点（`::before`，`background:currentColor` + 语义覆盖），保持现有文字标签不变——**不允许只靠颜色表达状态**（色弱用户）。

## 6. 实施映射（给开发的最小改动路径）

1. **先加 token 覆盖块**（放在现有 `body.dark` 规则处，`:186`）：

```css
body.dark{
  --bg:#070D13; --bg2:#0D1922;
  --card:#182633; --card2:#20323F; --card3:#293F50;
  --line:#354C60; --line-strong:#6A8799;
  --txt:#E8F0F7; --dim:#96ADBE;
  --track:#4A6577; --fill:#34D399;
  --blue:#7CC4F8; --green:#7BE495; --gold:#F5B94A; --deep:#7CC4F8;
  background:linear-gradient(160deg,var(--bg),var(--bg2));
  color:var(--txt);
}
```

这一块能自动修掉 `.chip / .tag / 输入框 / .stat .k / .sub / .bar-top` 的多数问题（它们本来就用这些变量）。

2. **删掉/改写会压过变量的组件规则**：`body.dark .card{background:#16242f}` 改为 `background:var(--card)`；`.state / .b-stop / .b-ghost / .mini-btn / .mbox / .menu / .cal .d / .cal 各状态 / .act3 / .tag / .ph-in` 按第 5 节逐条覆盖（尤其日历的状态选择器）。
3. **inline 色改 class**：`#errBar`、`#actWarn`（建议改结构，避免以后每加一个主题都要 `!important`）。
4. **JS 内联色替换**（这些颜色不写在 CSS 里）：
   - `#c0392b` → `#F87171`；`#22a06b / #12a877` → `#34D399` / `#7BE495`
   - `#e08a12 / #f0a02a` → `#F5B94A`；`#4aa8f0 / #8fd0ff` → `#7CC4F8`
   - 涉及位置：`resDiff.style.color`、历史条 `.hbar` 渐变、时薪轨迹线/点、日历金额字、奖牌/金色文案
5. **验收顺序**：亮色回归（现有浅色不变）→ 深色对比度脚本核 → 真机截图（深色 + 浅色各一张）→ 最后再合入。

## 7. 验收标准（5 条，可直接执行）

1. **无纯白面**：深色模式下，用 DevTools 检查 `.card / .chip / .tag / button / .mbox / .menu / #sheet / .cal .d / input / select` 的计算后 `background-color`，**没有** `rgb(255,255,255)`；`#errBar / #actWarn / .act3 / .ph-in` 同理。
2. **文字对比度**：主文字对卡片 ≥4.5:1（实测 13.37），次文字 ≥4.5:1（8.96），弱文字对卡片 ≥4.5:1（6.61）；表头、标签、说明文字均按弱文字处理。
3. **主数字**：渐变两端 `#4FD1C5 / #7BE495` 对卡片 ≥4.5:1（8.25 / 9.81），深色截图中主数字清晰可辨、不发飘；切到浅色后原渐变不变。
4. **进度条与右侧文案**：轨道对卡片 ≥2.5:1（2.51）且 1px 描边可见；填充对轨道 ≥3:1（3.19）；右侧「32.9% · 还差 ¥302.29」文字 ≥4.5:1（8.96 / 8.74）。
5. **状态与日历可辨**：工作中/已下班/未开始三态的文字/描边对比均 ≥3:1（11.80/3.39、11.12/3.10、8.90/3.48），且**不只靠颜色**（有文字标签 + 圆点）；日历今天环 ≥3:1（10.41），已上/休息/假日/非本月四类格子互不混淆。

## 附：下班小结「第 N 个上班日」文案与口径（本次一并定稿）

**结论：统一叫「上班日」，口径 = 已存档且 `earned > 0` 的日子。**

理由：
- 「上班日」是用户心里已有的词（真上了班才算）；休息、病假、带薪假只是**标记**，不等于上班，不应算一天。
- 「有记录日」听起来中性，但会把「标了休息、0 元的记录」也算进去，用户会问「我明明没上班，为什么第 N 天变多」；不如收紧口径，文案不动。
- 当前工作区（v30.02 未提交）已把 `monthTotal` 改成只在 `earned>0` 时 `days++`（`index.html:600-604`），与这个口径一致；**只剩文案没改**。

文案改法（替换 `index.html:1200` 一处 + 展开行一处）：

| 位置 | 现在 | 改为 |
|---|---|---|
| 一行小结 | `今天上班 7h00m，¥450.57。这个月第 12 天，累计 ¥5,412.68。` | `今天上班 7h00m，¥450.57。这个月第 12 个上班日，累计 ¥5,412.68。` |
| 展开第二行 | `本月：第 12 个上班日，累计 ¥…` | 不变（已经是「上班日」，口径与上面统一） |

配套：
- 若某天只标记未存档（`earned=0`），不计入「上班日」，也不计入「累计」（累计本来只统计存档金额，行为不变）。
- 当天立即存档导致 `earned=0` 时，今天不计入；小结显示此前已计入的天数即可，不需要特殊文案。
- harness 第 61 组有断言 `/这个月第 [0-9]+ 天/`，改文案时同步改成 `/这个月第 [0-9]+ 个上班日/`（只改断言文案，不改断言数量）。
- 不采用「第 N 个有记录日」：口径更绕、和用户直觉冲突，且要额外解释「为什么 0 元也算」。如果未来要展示「本月有记录天数」，另起一句「本月已记录 N 天」，不要混进「上班日」。
