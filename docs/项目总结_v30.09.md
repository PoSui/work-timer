## 四、立起来的流程

1. **开发只 commit + tag，绝不 push**；发布由 Lead 从 tag 解包后通过 GitHub API 推（沙箱内 `git push` 会被拒：`cannot create standard input pipe for remote-https`）。
2. **每版必须先过 pm 验收**，验收在 tag 独立解包环境复跑，不读工作树；报告落 `docs/验收报告_vNN.NN.md`。
3. **版本号规则**：只修 bug 用两位小数 `vNN.NN`（最多 .99），新增功能才进位；`index.html` 的 `.brand` 是唯一来源，title/README/台账必须跟它相等。
4. **发版门禁顺序**：升版本 → 写台账行 → 跑 harness/idb/selfcheck → commit → pm 验收 → Lead 从 tag 推。
5. **汇报口径**：结论 → 交付 → 风险 → 需拍板 → 下一步（见 `docs/老板汇报约定.md`）。

## 五、踩过的坑与教训（比功能更值钱）

1. **markup 与脚本漂移**：v24 线上缺 `iMode/iMonths/btnMini` 等节点，`fillForm()` 里 `getElementById(...).value` 抛 TypeError，boot 在 `render()` 前中断 → 页面静态 ¥0、无向导、点按钮没反应。补了「HTML 与脚本无 id 漂移」断言 + selfcheck id 完整性检查。
2. **测试桩会掩盖真实缺陷**：harness 的 `getElementById` 对任意 id 都造桩对象，所以 140 条全绿也没拦住缺节点。教训：桩要"只认真实存在的 id"。
3. **自检自己糊弄自己**：曾出现版本项只查"存在"、innerHTML 是 `ok(true)` 恒绿 → 删一行、塞未转义代码也 exit 0。现在全部改成严格相等 + 真扫描 + 反证模式。
4. **误推半成品**：一次 `git add -A` 把别人未完成的代码提交并推上线（坏 3 分钟，用 tag 回滚）。此后仓库根禁放临时脚本，`.tmp/` 进 `.gitignore`。
5. **默认值代表产品人格**：把 9800 写进默认值，等于让每个新用户看到你的工资。改回通用默认 + 首开向导。
6. **"爽感"是错的基调**：闪烁/连击/徽章被否（「打工是一个很长很复杂的事情，第一反应是反感」）→ 改为确定、可核对、有支撑感（对账、口径、长期视角、安静小结）。
