## 发现的问题（按严重度排序）

**P1 阻断：无。** 三个线上阻断 bug 均已核销：

- 设置区全空：根因是 HTML 缺 `iMode/iMonths/btnTheme` 导致启动 TypeError、后续绑定全不执行；v26 已补回（`index.html:192,271,272`），`fillForm` 正常赋值，harness 第 21/47 组通过。
- 点开始没反应：同一 TypeError 的连带；现 `startTimer` 正常绑定并执行，含薪资/工时校验（harness 第 3、46 组通过）。

**P2 体验：**

1. **小窗紧凑版不生效（第 17 项 ❌）**。点「小窗」只是开出一个 430×380 的**普通完整页面**：`app.v8.js` 里没有任何 `?mini=1` 解析，`body.mini` 不会被添加；而且 CSS 侧 `body.mini` 依赖的 `#mainCard/.big/.grid3/.cell/.foot/#miniHint` 在当前页面都不存在（主卡是 `.card.main`），就算以后补上 query 解析，主卡也会被 `:not(#mainCard)` 规则一起隐藏。README 与线上宣传的「迷你小窗」实际不可用——这是历史遗留（非 v26/v27 引入），不阻断核心计时，建议列为 v28 首项：启动时读 `location.search` 加 `body.mini`，并把选择器改成 `.card.main` / 当前实际类名。
2. **版本标识未跟进**：`index.html` 的 `<title>` 与页面 brand 仍是 **v26**（`:6,:189`），而 HEAD 已是 v27。推送后用户刷新看不出是不是新版，验收报告/commit 与页面版本对不上。建议发版前统一 bump（或让 inject/发版脚本自动改 title 与 brand）。
3. **首开无「默认值请改成你的」提示**：不弹向导后，任何人打开线上页都会直接看到 9800/08:30 这套数字（用户本人数据）。对单人工具可接受，但公开 URL 会暴露该默认值；建议首屏加一条可关闭提示「默认值已填，点设置改成你的」（不恢复强制向导）。

4. 备份导入只能粘贴整段 JSON 文本，无文件选择；备份内 `ver:"v21"` 硬编码；导入只做 `JSON.parse` + 粗类型判断，不校验版本/字段，脏数据可写进存储。建议加文件选择 + `ver` 白名单 + 失败不落地。
5. v19 起的目标「点金额改值/排序/✅」三处改动**没有自动化断言**；本期构成「合计 = 本期已赚」也没有交叉断言。建议各补 1–3 条，防回退。
