## 发现的问题（按严重度排序）

### P1 阻断（必须修，修完复验）

**差额归因把「估算里已经折算过的类型」再加一遍，结论与差额对不上。**

复现（SET27：月薪 9800、21.75 天、发薪日 15；本期估算满勤 = ¥5406.90，日薪 ¥450.57）：

1. PM61：10-20 病假、10-21 休息、10-23 加班 2 倍；实际填 `5226.67`（恰好等于估算）→ 页面显示差额 **¥0.00**，结论却是：
   > 差额主要来自 1 天休息（−¥450.57）和1 天加班（+¥450.57），其余是折算偏差（+¥180.23）。
2. PM62：只标 10-20 病假，实际=估算（5226.67，diff 0）→ 结论「差额主要来自 1 天病假（−¥180.23），其余是折算偏差（+¥180.23）」。
3. PM66：只标病假，实际比估算少 1500（3726.67，diff −1500）→ 结论「差额主要来自 1 天病假（−¥180.23），其余是折算偏差（−¥1319.77）」；归因区还写「当月工作日 13 天，按 21.75 天折算，本身会有几十元偏差（约 −¥1319.77）」——1319.77 显然不是「几十元」。
4. PM69：病假/休息/带薪/加班四类同现、实际 5000 → 结论只点「休息（−450.57）和加班（+450.57）」，两者相互抵消，真正有净影响的病假（−180.23）反而被塞进「折算偏差」。

根因（`_tests/app.v8.js`）：

- `periodTotal`（`:296-305`）用 `dayValue`（`:175-192`）逐日累加，**estimate 本身已经按病假 60%、休息 0、加班倍率折算过**；
- `actualAttribution`（`:324-342`）又按「相对满勤」把病假 `−0.4×日薪`、休息 `−日薪`、加班 `+(倍率−1)×日薪` 加回，得到 Σimpact = estimate − 满勤应得；
- `showActualResult`（`:412-439`）令 `residual = rec.diff − Σimpact`，于是残差 = 实际 − 2×估算 + 满勤应得，天然多出一份估算偏差；
- 结论按单个 `|impact|` 排序取前 2（`:428-433`），抵消项（休息/加班）会一起被说成「主要来自」，净影响最大的项反而被隐藏。

> 另按任务口径点明：代码里的「折算偏差」不是独立测量，它是 `residual = rec.diff − Σimpact`（`:415`）的残差，只能当「未解释部分」，不能当作被验证过的量；本次 P1 正是把残差当成了「折算偏差」并给它编了与数量级不符的解释。

修法建议（产品口径，二选一，不要只改文案）：

- A. 把「估算」明确成**满勤应得**（`工作天数×日薪`），结果页另列「折算后估算」，`diff` 相对满勤计算 → 归因与 `diff` 同基；
- B. 保留现在的折算后 estimate，则结果页不再按类型加回影响，把归因改成「估算已含这些折算」的说明，差值只解释未归类部分。
- 结论句只列**净贡献**（同类型先合并，休息/加班抵消时写成「休息与加班基本抵消」），不再按单条绝对值排序；`|residual|` 超过约 100 元时，文案改成「其余 X 元暂未归类（可能含社保/个税/填错）」，删掉「本身会有几十元偏差」的固定量级说法；带薪 ¥0 继续排除。
- 第 51 组现在断言「休息/加班排在病假前」，**依赖的正是这个缺陷行为**；修 P1 时要同步改成「结论与 rec.diff 一致」的断言（差额 0 时不得出现「差额主要来自」），并补 PM61/PM62 两类用例。
