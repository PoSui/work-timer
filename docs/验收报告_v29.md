## 发现的问题（按严重度排序）

### P2-1（不阻断，但建议发布前顺手修）「+ 添加一段」会立刻造出一条错误阶段，并让「现在值」变错

复现（PM98，正常路径，不是手动改乱）：2026-11 首次打开，阶段只有 `{2026-11, 9800, 21.75, 7}`（时薪 ¥64.37）。点一次「+ 添加一段」，列表变两段且**同月重复**：`{2026-11, 9800, 21.75, 8}`。原因是按钮用 `S.hours` 建新段，而首次启动时 `S.hours` 还是 undefined，`hourlyOfPhase` 兜底成 8 → 新段时薪变成 ¥56.32；结论又因两段同月（`mv=0`）走「目前只有一段记录」分支，卡片出现「只有一段记录 + 现在值 ¥450.57」而列表明明有两行。

判 P2 而不是 P1：主界面金额、对账、存档都不受影响，用户可删掉错段；但这是**正常按钮一次点击就让「现在值」变化、并说「只有一段记录」**，正好打在「可信」这个卖点上，建议 v29 发布前修或至少 v29.01 修：新段沿用上一段的 `days/hours`（`hours: paidHours() || last.hours`），同月已存在时改为覆盖/提示，或新增后聚焦月份输入并做 `YYYY-MM` 校验。

### P3（建议，不阻断）

- **P3-1 乱序/非法月份无校验**：PM95 把两段月份颠倒 → 文案「目前只有一段记录：从 2026-11 起」且「现在值」取到更早阶段；PM97 起始月填 `abc` 被原样存入并渲染。取舍 #7 已声明「不强制排序」，但至少应在 `change` 时校验 `^\d{4}-(0[1-9]|1[0-2])$`，或按 `from` 排序渲染前提示「阶段顺序与月份不一致」。
- **P3-2 当前月薪为 0 时仍显示「现在值」**：PM96 把月薪改回 0 后，卡片保留旧末段并称「现在值 ¥514.94」，实际当前时薪为 0。建议 `monthlyPay()<=0` 时隐藏卡片，或把末段改称「最近记录」。
- **P3-3 SVG 会被横向拉伸**：`index.html:1178` 用 `preserveAspectRatio="none"`，而 CSS 是 `width:100%; height:118px`（`:224`），容器宽于 300 时圆点会变椭圆、文字横向拉伸。建议改 `xMidYMid meet`，或按实际宽度重算 viewBox。
- **P3-4 折线 X 轴按数组序号等距**，不按月间隔：跨 1 个月和跨 12 个月在图上视觉距离相同，容易被读成时间轴。建议按 `monthIdx` 做 X 比例，或图下加一句「横轴为阶段顺序，非等比例时间」。
- **P3-5 小跌幅的口径**：<5% 分支优先于负号，−3% 会显示「基本没动（…，3%）」不含「降了」；`Math.round` 也可能把 4.6% 显示成 5% 而文案仍「基本没动」。我认为这是合理取舍（避免为 2% 的波动说「降了」），建议把数字改成「变化 3%」以免正负误读。
- **P3-6 「三句」是三类模板**：实际渲染 2 行（涨跌/没动句 + 同样 8 小时句），「基本没动」与前句互斥；若产品定义是三条同屏，需要澄清（当前实现与测试一致）。
- **P3-7 IDB 水合缺正式断言**：代码路径已实测通过（18/18），但 `idb.test.js` 没有 phases 用例；建议把探针第 4 组并入正式测试，防止以后改动 `snapshot/hydrate` 时静默丢阶段。
