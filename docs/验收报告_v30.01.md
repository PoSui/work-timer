## 发现的问题（按严重度排序）

**P3-1（新发现，不影响金额）休息标记日会被算进「本月第 N 个上班日」**
- 复现：11-02 标「休息」（`records["2026-11-02"]={type:"off",earned:0}`），11-03 正常打卡存档 → 小结展开行显示「本月：第 **2** 个上班日，累计 ¥450.57」，而本月实际只上了今天 1 天。
- 根因：`monthTotal()`（`app.v8.js:115-126`）对本月每条记录都 `days++`（不论 `earned` 是否为 0）；休息标记会留一条 `earned:0` 的记录。累计金额本身是对的（`sum+=earned||0`）。
- 影响：只影响「第 N 天 / 第 N 个上班日」这个计数文案；金额与主界面同源、无错。
- 建议：`days` 只统计 `earned>0`（休息日不计「上班日」），或把文案改成「本月第 N 条记录」——二选一即可，属 v30.02 级小修。

**P3-2 非法月份静默拒绝，无任何提示**（`docs/测试记录.md` v30.01 取舍 2 已声明）
- 输入 2026-13 回车后输入框回弹原值，但无错误提示，用户可能不知道为何没改上。产品基调是「安静」，可接受；若日后加提示，建议只改 placeholder/边框，不弹条。

**P3-3 编辑阶段月份后自动按时间排序，当前行可能跳到别处**（v30.01 取舍 3 已声明）
- 稳定排序（同月按薪资），无动画提示；用户可能一时找不到刚改的行。

**P3-4 同月「+ 添加一段」覆盖末段**（v30.01 取舍 1 已声明）
- 同月只保留最后一次；若用户以为能记录「月中调薪前后」两段，会覆盖。属于为避免曲线同列堆点的取舍，建议按钮加一句短提示（如 title"同月覆盖"）。
